## Locked design decisions

### Task & join
- **Task**: binary nucleus segmentation (image → mask).
- **Join**: horizontal — BraTS-style `DirectoryJoin` over per-TDP folders. Each TDP holds different samples with the same schema.
- **Privacy**: **DP wired but disabled by default** (`is_private: false`). `privacy_params` populated with sensible Opacus defaults (`max_grad_norm=1.0, epsilon=8.0, delta=1e-5`) so enabling DP is a one-line `is_private: true` flip. Harness reads `is_private` + `privacy_params.{max_grad_norm, epsilon, delta}` ([src/train/pytrain/dl_train.py:79-186](../../src/train/pytrain/dl_train.py)). Note: `noise_multiplier` and `target_epsilon` are Opacus internal parameter names, **not** config keys.

### TDPs
**2 TDPs**, grouped from the 7 centers actually present in the Kaggle source data, balanced by sample count:

| TDP | Centers | Samples |
|---|---|---|
| `oral_cyto_A` | 11, 02, 03 | 349 |
| `oral_cyto_B` | 12, 06, 07, 10 | 390 |

Centers are identified by the **first 2 chars** of the filename.

### Source data
- Kaggle dataset: `abhijeetptl5/oral-cytology-dataset` (739 geojson + 739 png = 1,478 files; ~3 GB).
- All files flat under `oral_cytology_dataset/`. No nested per-center directory.
- Filename scheme: `<CC><XX><NNNNNN><L>_<x>_<y>.{geojson,png}`
  - `CC` (2 digits) — **center ID** (partition key)
  - `XX` — scanner/sub-protocol variant (mostly `OC`, also `O0`, rarely `O2/O4/O5/O6`)
  - `NNNNNN` — case/slide ID
  - `L` — `M` (malignant) or `P` (premalignant), sample-level label (not used as join key)
  - `_x_y` — tile coordinates within the source WSI
- Each geojson is a list of polygons (nucleus annotations). Each paired png is the corresponding RGB tile.

### Mask preparation
- **Preprocess-time rasterization.** Each TDP's preprocess script rasterizes its geojsons to binary `_seg.png` files using OpenCV `fillPoly` (logic lifted from `~/oral_cyto_dataset/cyto_dataset.py::_geojson_to_mask`).
- Output layout per TDP, matching BraTS's paired-image structure:
  ```
  data/<tdp>/preprocessed/oral_cyto_<sample_id>/
    <sample_id>_img.png   # RGB tile from Kaggle
    <sample_id>_seg.png   # binary mask, same HxW
  ```
- This keeps `dataset_config.type=directory, structure_type=paired` and avoids any new framework dataset type.

### Model
- Declarative UNet via BraTS's `model_config.json` engine (`ModelFactory.load_from_dict`). **Not** `smp.Unet`.
- Adjustments vs BraTS UNet:
  - `in_conv.in_channels = 3` (RGB stain — color matters)
  - Output stays binary (1-ch sigmoid)
- `src/model_constructor.py` lifted **byte-identical** from BraTS (the framework pattern: every scenario carries a local copy).
- `src/save_base_model.py` lifted from BraTS (scenario-agnostic).

### Losses & metrics
- Loss: `dice_loss + 2 * l1_loss` (same expression as BraTS).
- Metrics: dice_score, jaccard_index, hausdorff_distance.

## Known quirks

- Encryption key IDs contain a stray underscore (e.g. `OralCyto_AFilesystemEncryptionKey`) because BYO's PascalCase regex doesn't consume underscores preceding uppercase letters. Renamed to `OralCytoA` / `OralCytoB` (no underscore) on 2026-06-01 after Phase 4D discovered Azure Key Vault enforces `^[0-9a-zA-Z-]+$` on key names. The original BYO PascalCase regex bug remains in `build-scenario.sh` upstream — use all-lowercase TDP names (`oral_cyto_a`, `oral_cyto_b`) when re-running BYO to avoid this.
- Contract carries NO privacy bounds and `is_private` is false. This is the only CCR-deployable DP-off state per [policy.rego](../../src/policy/policy.rego)'s either/or rule. Do not add bounds to the contract without also flipping `is_private` to true.
- `export-variables.sh` fails `bash -n` until placeholder values (e.g. `<azure-location>`) are replaced with real values. This is template behavior inherited from BraTS, not a bug. Fill placeholders before sourcing the file.
- `2-create-akv.sh` has its two `az role assignment create` lines commented out for this scenario's deploy. Reason: the deployer's account already holds `Key Vault Crypto Officer` at the subscription scope (inherits down). The original lines require `User Access Administrator` or `Owner`. **On a fresh subscription where the deployer lacks KV roles, uncomment lines 22-24 before running** (and ensure the deployer has UAA/Owner).
- ONNX migration attempted twice (most recent revert: 2026-05-28). Two stacked framework-level incompatibilities block ONNX as `model_format` for this scenario:
  1. [`dl_train.py:294`](../../src/train/pytrain/dl_train.py#L294)'s `torch.onnx.export()` defaults to the dynamo exporter, which is incompatible with `onnx2pytorch v0.5.3`. One-line fix (`dynamo=False`) submitted upstream at `fix/onnx-export-dynamo-false` in the user's fork.
  2. Even with that patch, `onnx2pytorch`'s Reshape op fails on the Reshape+InstanceNorm+Reshape sequence that `GroupNorm` exports to, under both dynamo AND legacy TorchScript exporters. Requires `onnx2pytorch` upgrade or `GroupNorm` → single-op normalizer replacement to resolve.

  Shipping safetensors. CCR compatibility is unaffected: the declarative `model_config.json` DSL satisfies the no-TDC-code requirement regardless of which weight-storage format (safetensors or ONNX) is used. The DSL is what makes CCR-safe model definition possible; safetensors is just the weight blob format and matches BraTS convention.

## Phase split

- **Phase 1 (now)**: local pipeline runnable end-to-end on cleartext data. Includes config/, src/, deployment/local/, ci/, modeller/ skeleton, policy/ placeholder, BYO-generated Azure scripts, BYO-generated contract template.
- **Phase 2 (deferred)**: fill in deployment values in [export-variables.sh](./export-variables.sh) (Azure subscription, location, resource group, key vault, storage account), fill in TDC/TDP identities in [contract/contract.json](./contract/contract.json), and execute the encrypt/upload/deploy steps. The Azure scripts themselves should not need code changes — only values.

## Background (not surfaced in README)

The original paper claims 10 centers; the published Kaggle dataset only contains 7 (gaps at center IDs 01, 04, 05, 08, 09). Distribution is heavily imbalanced — centers 11+12 account for ~78% of samples. The 2-TDP grouping above is a deliberate balance choice, not the only defensible one. If we ever want to reproduce paper results faithfully, we'll need to obtain the missing centers separately.
